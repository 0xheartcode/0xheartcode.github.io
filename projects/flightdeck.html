PROJECT OVERVIEW

A self-hosted deployment control plane for containers with Railway-style ergonomics on your own hardware. A small Rust agent on each host discovers labelled containers and streams their logs, metrics and status over WebSocket to a TypeScript control plane and a React UI, with gated restart and redeploy from the browser.

KEY FEATURES

▲

MULTI-HOST AGENTS

A Rust agent per server, against Docker or a rootless Podman socket, with automatic reconnect and live event fan-out.

▲

HIGH AVAILABILITY

Postgres LISTEN/NOTIFY fan-out, OIDC/JWT role-based access, and a read-only operator audit trail.

▲

OBSERVABILITY

Durable log search via an optional Loki/Grafana/Prometheus stack, plus a notifications hub.

ARCHITECTURE

⬤

CONTROL PLANE

A TypeScript (Hono) service with two WebSocket endpoints, one for agents and one for browsers, keeping a bounded in-memory log tail per service and fanning events out to the UI.

⬤

PER-HOST AGENT

One small static Rust binary per server that discovers containers labelled flightdeck.enable=true via the bollard Docker API and forwards logs, reconnecting automatically.

⬤

SHARED WIRE CONTRACT

A versioned protocol package: zod schemas on the TypeScript side mirrored by serde structs in the Rust agent.
